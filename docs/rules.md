# 规则手册

20 条规则，权重合计 100 分。每条规则只有三种结果：通过 / 失败 / N/A（不计入分母）。

- **必须修**：会直接导致技能在被调用时失败或永远不被调用。
- **建议修**：能用，但触发率或可维护性会打折。
- **可选**：锦上添花。

## 触发力（D1，25 分）

> 判定对象是 `description`——模型只读这一段决定要不要用它。这一段写不好，正文写得再好也不会被触发。

| 规则 | 分值 | 级别 | 判定与阈值 |
|---|---|---|---|
| TRG001 | 8 | 必须修 | SKILL.md 顶部有 `---` 包裹的 frontmatter，且 `name`、`description` 均非空。缺失直接封顶 40 分。 |
| TRG002 | 6 | 必须修 | `name` 匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`、≤ 64 字符，且等于包的顶层目录名（zip 内首层目录或磁盘目录名）。 |
| TRG003 | 6 | 建议修 | `description` 长度 80–1024 字符。低于 80 模型难以区分场景，高于 1024 会被截断。 |
| TRG004 | 5 | 建议修 | 至少含一个触发语（`Use when` / `适用于` / `当你需要` / `whenever`），且至少有 2 组引号包裹的用户原话示例。 |

## 结构（D2，20 分）

| 规则 | 分值 | 级别 | 判定与阈值 |
|---|---|---|---|
| STR001 | 6 | 必须修 | 存在标题含 `What` / `Purpose` / `做什么` / `作用` 的章节。 |
| STR002 | 4 | 建议修 | 存在 `When` / `何时` / `什么时候` / `适用` 章节。 |
| STR003 | 4 | 必须修 | 同时存在 Input 与 Output 章节。 |
| STR004 | 3 | 建议修 | Steps 章节内的编号/项目符号条目 ≥ 3 条。 |
| STR005 | 3 | 可选 | 有 Tools/依赖章节，或正文提到运行时（python/node/bash/curl/api/脚本）。 |

## 可执行（D3，30 分）

> 权重最高的维度。原因：一份"读起来很好但跑不起来"的技能，价值接近于零。

| 规则 | 分值 | 级别 | 判定与阈值 |
|---|---|---|---|
| EXE001 | 8 | 必须修 | 正文有 ``` 代码块，或包内存在 `scripts/`。 |
| EXE002 | 6 | 必须修 | 正文引用的 `scripts/` `references/` `assets/` `examples/` 路径在包内全部存在。正文无引用时为 N/A。 |
| EXE003 | 6 | 必须修 | Input 章节 ≥ 40 字符且含格式/字段/示例（`|` 表格、代码块、`示例`、`schema` 等）。 |
| EXE004 | 5 | 建议修 | Output 章节 ≥ 30 字符且给出产物格式（`/\.md|\.json|\.csv/`、`格式`、`模板`、代码块）。 |
| EXE005 | 5 | 可选 | 提到失败/错误/兜底/边界/异常中的任意一种处理方式。 |

## 可维护（D4，25 分）

| 规则 | 分值 | 级别 | 判定与阈值 |
|---|---|---|---|
| MNT001 | 5 | 建议修 | SKILL.md ≤ 500 行。超过时应把细节移到 `references/`，靠分层加载。 |
| MNT002 | 4 | 可选 | SKILL.md > 30KB 时必须有 `references/`，否则分层加载失效。 |
| MNT003 | 4 | 建议修 | 存在 `examples/` 或任何文件名含 `demo` 的文件。 |
| MNT004 | 4 | 必须修 | 不含 `TODO` / `FIXME` / `XXX` / `待补充` / `待填写` / `占位符` / `lorem ipsum`。命中封顶 60 分。 |

## 分数与等级

```
总分 = 100 × Σ(通过的权重) / Σ(参与判定的权重)      # N/A 不进分母
总分 = min(总分, 红旗封顶)
```

| 分数 | 等级 | 结论 | 含义 |
|---|---|---|---|
| ≥ 90 | A | PASS | 可以直接发布 |
| 75–89 | B | PASS | 能用，但触发率会打折 |
| 60–74 | C | WARN | 结构在，执行细节缺失 |
| < 60 | D | FAIL | 还不算一个技能，只是一个想法 |

## 已知局限（诚实披露）

1. **占位符规则会误报**：示例代码里出现 `xxx` 作为占位变量名会被判为 MNT004。当前策略是宁可误报也不漏报——因为草稿态交付的代价更高。用 `--quiet` 看明细后可人工忽略。
2. **章节识别基于标题关键词**，把 `## 输入` 改写成 `## 需要什么` 会漏判。这是刻意的取舍：规则必须可解释，语义判断交给 LLM 那一层（见 C6 的 Web 版）。
3. **只查 SKILL.md 的内容**，不递归扫描所有文本文件里的密钥（性能取舍：一个包里可能有几百个二进制文件）。文件级只检查 `.env/.pem/.key` 这类高风险扩展名。
4. **不评判内容对不对**。它只能告诉你"结构是否完整、引用是否断裂、有没有草稿残留"，不能告诉你"这个技能的想法好不好"。
